# SUNRISE-2 モデル 再計算結果（Ver.23 準拠）

標準患者・上流固定の決定論的最適化。確率制約と焼きなましは廃止。
数値はすべて `scripts/` のスクリプトから再生成される。

## 結論（Implementation に返す値）

| 項目 | 値 |
| --- | --- |
| 初期菌数 | 2.00×10^10 CFU/膀胱（10⁸ CFU/mL × 200 mL） |
| 推奨 MOI | 3.29 粒子/CFU |
| 1 回投与量 | 6.59×10^10 粒子/回 |
| 投与間隔・回数 | 6 時間 × 12 回 |
| **コース総量** | **7.90×10^11 粒子/コース** |
| カナマイシン | 1 回 0.72 g 筋注 q12h（1 日 1.43 g、血中ピーク 35 µg/mL） |
| 終盤の接着数 m∞ | 90 粒子/菌 |
| A_cell 最大 | 814 分子/菌（有効窓内: はい） |
| 最悪位相での C̄^tot | 70.0 CFU/mL（閾値 10² の 70%） |
| 最悪位相での Δlog10 | 6.29 |

η_mech を見込む場合はコース総量を ÷ η_mech する。

> **渡すとき必ず添える 3 点。**
> 1. 治療達成は無菌化ではない。判定を通った条件でも細胞内区画に約 5.6×10⁴ CFU/膀胱 が残る（タスク 5）。「72 時間で菌がいなくなる」とは書かないこと。
> 2. 受容体数の制約に当たるのは MOI ではなく、コース終盤の接着数 m∞（上表では 90 粒子/菌）。
> 3. 低菌量の患者に MOI を掛け算してはいけない（タスク 6）。渡すべき不変量は D（粒子/回）。

## タスク 6 — 菌量依存

| 初期菌濃度 [CFU/mL] | 総菌数 [CFU/膀胱] | f_hit(0) | 最適 MOI | D/回 [粒子] | コース総量 [粒子] |
| --- | --- | --- | --- | --- | --- |
| 1.00×10^6 | 2.00×10^8 | 0.215 | 72.502 | 1.45×10^10 | 1.74×10^11 |
| 3.00×10^6 | 6.00×10^8 | 0.451 | 25.156 | 1.51×10^10 | 1.81×10^11 |
| 1.00×10^7 | 2.00×10^9 | 0.733 | 8.163 | 1.63×10^10 | 1.96×10^11 |
| 3.00×10^7 | 6.00×10^9 | 0.891 | 3.040 | 1.82×10^10 | 2.19×10^11 |
| 1.00×10^8 | 2.00×10^10 | 0.965 | 1.110 | 2.22×10^10 | 2.66×10^11 |

> **依頼書の予想と逆向きになった。** 菌量が少ないほど必要 MOI は**上がる**（10⁶ CFU/mL で 72.5、10⁸ で 1.11）。ただし実装の誤りではない。

理由は f_hit の律速領域の切り替わりである。f_hit = k_enc·C/(k_enc·C + k_washout + k_loss) の変わり目は **3.65e+06 CFU/mL**。これより菌が少ないと粒子は菌に出会う前に洗い流されるため、m = D·k_enc/(V(k_washout+k_loss)) となって菌量に依存しなくなる。不変量は MOI ではなく絶対粒子数 D のほうで、実際 D/回 は菌量 100 倍にわたって 1.45×10^10 – 2.22×10^10 粒子（1.53 倍）しか動かない。

> **出力単位への影響。** 依頼書は「必要量は菌数にほぼ比例するので MOI で渡せば Implementation 側の掛け算で済む」としているが、この比例が成り立つのは菌量が 3.7e+06 CFU/mL を上回る範囲に限られる。低菌量の患者には **D（粒子/回）を直接渡すべき**で、MOI を掛け算すると必要量を大きく過小評価する。

## タスク 8 — 検算

- `python -m sunrise.verify` の不変量チェックは全項目通過（下記参照）。
- **Table 9.4.50 の η ≥ 0.7575 は実装と照合が取れない。** 原稿の逆解き（分母 1+x^κ）では η = 0.7050、実装の形（分母 x^κ − ψ_min/ψ_max、ψ(MIC)=0 が厳密に成立）では η = 0.5440。原稿値の再現: False。**この数値は実装が確定するまで使わないこと。**
- 免疫項を飽和型に差し替えて安静時に固定すると Results の判定量は変わらない（Δlog10 6.2750 → 6.2750、C̄ 87.068 → 87.068）: **True**
- grid.py の較正バグ（較正値がワーカーにしか適用されない）と同型の構造は無い。`Params` は frozen dataclass で全ワーカーへ明示的に渡され、モジュールレベルの可変状態を持たない。親とワーカーの判定量一致: **True**

## 申し送り（判断が必要な項目）

| 項目 | 状況 | 影響 |
| --- | --- | --- |
| τ_P の下限 | 膀胱内注入の実施可能回数が未確定（臨床側へ照会中） | τ_P 3 h なら m∞ 36、6 h なら 90。受容体数への要求が 2.5 倍動く |
| ν の不確実性範囲 | 基準 32.3 は確定、範囲 10.7–34.9 は旧シナリオのまま | 許容限界は ν ≥ 25.4。現在の範囲下端 10.7 では判定が落ちる |
| η_mech | 計算に入れていない | コース総量が 1/η_mech 倍に増える |
| Table 9.4.50 の η ≥ 0.7575 | 実装と照合が取れない | 照合まで使用しない |
| 出力単位 | MOI は高菌量でのみ掛け算可 | 低菌量患者には D を直接渡す |
| 判定閾値 10² / 10³ | 10² は診断閾値であって治癒閾値ではない | C̄^tot の床が 50 CFU/mL なので、10² では余裕が 2 倍しか取れない |

もっとも効くのは **ν の下端**と **τ_P の下限**である。許容限界表で ν ≥ 25.4 が出ており、CPI 班が範囲を 10.7–34.9 のまま置いている以上、この 1 点で設計が成立するかどうかが決まる。CPI 班への照会が最優先。
